# Cancelling an MBDyn run

While a simulation is running, select **Cancel simulation**. The application keeps the editor busy until the solver has actually stopped and the pending run request has returned. A cancelled run is identified separately from a failed or successful run; use **Run log** to inspect retained partial output. The generated deck, project snapshot, log and summary remain in the run folder when execution had started. A cancelled trajectory is not accepted as a completed result and does not create a valid results CSV.

The desktop host blocks its normal close action while a run is busy. Cancel the run first, wait for the stopped state, then close. Browser page dismissal sends a best-effort cancellation beacon. An abrupt browser, operating-system or application crash can prevent that signal; it does not prove cancellation. A run without a delivered cancellation remains subject to the existing solver deadline. The backend cannot safely infer full client disconnection from a read-side TCP EOF, which can also be a valid HTTP half-close.

A solver request uses a random 128-bit run token. The local same-origin endpoint `POST /api/run/cancel` accepts `{ "runToken": "..." }` only for that request. A matching cancellation that arrives before registration is retained briefly and applied if that exact request starts; a different active run is never cancelled. Completed tokens cannot be immediately reused. Older API requests without tokens remain supported but cannot be cancelled by this endpoint.

Windows-native solvers run in an owned Windows Job Object. POSIX-native solvers run in an owned process group. For WSL, MBDyn is started through a guest-side supervisor using `/usr/bin/setsid`; after session readiness, cancellation kills that owned guest process group rather than only terminating `wsl.exe`. Normal MBDyn execution and an intentionally TERM-ignoring descendant were tested in the configured distribution; an unrelated guest process continued. Programs that deliberately escape the guest session or process group are outside this guarantee. If the guest supervisor cannot confirm shutdown, the app reports a cleanup error rather than claiming cancellation.

Real process, local HTTP and WSL process-group regressions are in `backend/test_cancellation.py`. Set `MBDYN_TEST_WSL_CANCEL=1` to opt into the real WSL lane on a configured Windows host. `tests/cancellation-ui.mjs` tests the editor interaction and request-token flow with controlled delayed responses; it does not replace the real process checks.
